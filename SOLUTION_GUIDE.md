# Решение проблемы подключения к базе данных FM Edu

## 📋 Обзор проблемы

У тебя есть проект FM Edu (https://fm-edu-five.vercel.app/) с двумя системами данных:
1. **JSON-based система** (`lib/db.ts`) - используется в большинстве API endpoint'ов (mock данные)
2. **Supabase система** (`lib/supabase.ts`) - настроена, но не используется

**Суть проблемы:**
- ✅ Supabase база подключена и работает
- ✅ 7 таблиц созданы (profiles, students, users, project_requests, team_rooms, team_room_members, team_chat_messages)
- ❌ Таблицы пустые (нет данных из JSON файлов)
- ❌ API endpoint'ы используют mock данные вместо Supabase
- ❌ RLS политики блокируют вставку данных
- ❌ Не хватает таблиц для учебных данных (topics, assignments, tests и т.д.)

## 🚀 Пошаговый план решения

### Шаг 1: Исправить RLS политики и создать недостающие таблицы
**Что нужно сделать:**
1. Открой Supabase Dashboard: https://supabase.com/dashboard/project/vjzchdkiitiujyslydyn/sql
2. Открой SQL Editor
3. Скопируй и выполни SQL скрипт из файла `complete_setup.sql`

**Это решит:**
- ✅ Временно отключит RLS для миграции данных
- ✅ Создаст недостающие таблицы (topics, assignments, tests и т.д.)
- ✅ Настроит правильные RLS политики
- ✅ Создаст индексы для производительности

### Шаг 2: Запустить миграцию данных из JSON в Supabase
**После выполнения SQL скрипта:**
1. Открой терминал в папке проекта FM-Edu
2. Запусти исправленный скрипт миграции:

```bash
cd FM-Edu
node migrate_data_fixed.js
```

**Что произойдет:**
- ✅ Данные студентов из `data/students.json` загрузятся в таблицу `profiles`
- ✅ Данные пользователей из `data/users.json` загрузятся в таблицу `users`
- ✅ Будут созданы UUID для всех записей
- ✅ Данные из других JSON файлов будут готовы к миграции

### Шаг 3: Мигрировать остальные данные (опционально)
Создай дополнительные скрипты для миграции:
- Темы из `data/topics.json` → таблица `topics`
- Задания из `data/assignments.json` → таблица `assignments`
- Тесты из `data/tests.json` → таблица `tests`
- Материалы из `data/materials.json` → таблица `materials`

### Шаг 4: Обновить API endpoint'ы для работы с Supabase
**Основные файлы для обновления:**
1. `app/api/admin/users/route.ts` - сейчас использует mock данные

**Что нужно изменить:**
- Заменить mock данные на запросы к Supabase
- Использовать `getSupabaseClient()` из `lib/supabase.ts`

### Шаг 5: Тестирование

## 🔧 Технические детали

### Проблемы которые были решены:

#### 1. **Проблема с ID форматом**
- **Проблема**: JSON данные имеют ID типа `"1787000495577-1letv3yj9"` и `"mock_leader_1"`
- **Решение**: Используем `crypto.randomUUID()` для генерации правильных UUID в миграции

#### 2. **Проблема с RLS политиками**
- **Проблема**: RLS политики блокируют вставку: "new row violates row-level security policy"
- **Решение**: SQL скрипт временно отключает RLS, затем настраивает правильные политики

#### 3. **Проблема с недостающими таблицами**
- **Проблема**: Нет таблиц для учебных данных (topics, assignments и т.д.)
- **Решение**: SQL скрипт создает все необходимые таблицы
